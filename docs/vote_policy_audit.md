# Town vote policy audit

The [raw audit](../runs/town-vote-20261004-094946/vote_audit.json) compares
frozen `Qwen/Qwen3-4B-Instruct-2507` with the adapter from the first RL run.
Both use greedy legal-target votes against the same seeded random policies on
game seeds 50000–50023. The audit used the same model setup as the trainer and
reproduced its held-out wins.

| Measure | Frozen Qwen | Trained adapter |
| --- | ---: | ---: |
| Town wins | 16/24 | 15/24 |
| Town votes targeting Mafia | 64/148 | 59/160 |
| Detective votes targeting Mafia when privately known | 2/4 | 7/10 |
| Votes for P0 when legal | 0/73 | 0/79 |
| Votes for P3 when legal | 31/81 | 60/74 |

The number of votes and known-Mafia opportunities differs because changed
votes lead to different game paths. The Detective counts are too small for a
reliable improvement claim.

To isolate the policy change, we also gave both models the **same 148 frozen
player observations** from the untrained games. The adapter chose a different
target 44 times. Among those changes, 21 moved from Mafia to a Town target and
10 moved from a Town target to Mafia. Thirty-three of the 44 changed targets
were P3. P0 was never chosen in either full-game evaluation despite many legal
opportunities. This is strong evidence of seat-label preference in the current
single-digit action representation; it does not establish that the model has
learned to infer Mafia identity from the transcript.

Three game outcomes changed: seeds 50011 and 50015 switched from Town wins to
Mafia wins, while 50020 switched from a Mafia win to a Town win. Twenty-four
games are useful for diagnosis, but not enough to claim a small win-rate change.

## Controlled label swap

We tested the frozen policy on the **same observation** after consistently
swapping two player labels throughout its visible history, private facts, and
legal targets. We mapped the chosen alias back to the original person.

| Swap | Views where both were legal | Changed actual target | Chose original P0 before / after |
| --- | ---: | ---: | ---: |
| P0 ↔ P3 | 38 | 17 | 0 / 8 |
| P0 ↔ P5 | 35 | 25 | 0 / 15 |

This confirms that the arbitrary labels influence the choice. The game rules
and legal-target mask include P0. The likely design problem is that the policy
asks for a single digit and compares the model's next-token scores for `0`–`5`
without accounting for label preference. The swap test does not isolate the
exact contribution of digit-token preference versus the prompt wording or
ordering of names in the observation.

## Frozen candidate-wise probe

We tried [one yes/no question per legal candidate](../src/training/candidate_vote.py)
with the frozen Qwen model, keeping the game seeds and opponents fixed. This
uses the same Yes and No answer tokens for every candidate, so it avoids
directly comparing the model's raw `0`–`5` token scores. The
[raw result](../runs/candidate-vote-seeds-50000-50023.json) shows:

| Measure | Original frozen vote policy | Candidate-wise frozen policy |
| --- | ---: | ---: |
| Town wins | 16/24 | 10/24 |
| Town votes targeting Mafia | 64/148 | 42/144 |
| Votes for P0 when legal | 0/73 | 10/76 |
| Known-Mafia Detective votes targeting Mafia | 2/4 | 6/6 |

The candidate-wise policy still changed its actual target on 19 of 38
identical observations when P0 and P5 were swapped. It reduces the outright
P0 avoidance, but does not remove label sensitivity or improve game outcomes.
We should not train this representation as-is.

## Label-invariant candidate probe

We then gave every candidate the same `SUSPECT` name and position in the
prompt, renamed the voter `YOU`, and renamed the other players consistently
throughout public and private events. The
[raw result](../runs/candidate-centered-seeds-50000-50023.json) shows:

| Measure | Centered frozen policy |
| --- | ---: |
| Town wins | 9/24 |
| Town votes targeting Mafia | 53/170 |
| Votes for P0 when legal | 30/81 |
| Known-Mafia Detective votes targeting Mafia | 9/10 |
| Actual targets changed after P0 ↔ P3 relabeling | 0/37 |
| Actual targets changed after P0 ↔ P5 relabeling | 0/38 |

The invariance check passed, but the game result worsened on these seeds. This
representation is correct about arbitrary labels; it does not create evidence
that the voter lacks. In the current training games, speech is generated by a
random policy: it is either empty or a random accusation, and it never uses a
Detective's private result. A Detective can often vote correctly when they
know Mafia, yet other Town players cannot learn that fact from the discussion.

These 24 seeds have now guided policy design and are **development cases**.
Use fresh seeds and stronger opponents before claiming a general win-rate
improvement.

## Small RL check of the invariant vote representation

We ran a separate three-update LoRA experiment using the centered candidate
question as the trainable Town vote action. It used 12 training games
(seeds 3000–3011) and eight fresh evaluation games (seeds 60000–60007).
The [saved report](../runs/town-centered-vote-20261004-110540/report.json)
records the settings and numeric metrics.

| Eight held-out games | Town wins |
| --- | ---: |
| Random Town votes | 5 |
| Frozen centered candidate policy | 4 |
| Trained centered candidate policy | 3 |

All 72 Town vote decisions in the training batches contributed to a finite
policy gradient; LoRA weights changed, and the final evaluation had no invalid
votes or forfeits. The model update worked, but this small sample provides no
evidence of improved play. The run saved an adapter and metrics, not full
per-game transcripts.

## Proposed next experiment

Design an information-sharing discussion policy before more vote training.
Start with a frozen Town speaker that can announce a Detective's actual
investigation and let Villagers react to public claims. Then study whether
votes move in response, compare against scripted Mafia claims, and only then
choose an RL action and reward. Keep final evaluation on fresh seeds.
